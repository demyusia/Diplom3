# Часть 3. Автоматизация UI-тестирования для Stellar Burgers

Репозиторий содержит фреймворк для автоматизированного тестирования пользовательского интерфейса (UI) космической бургерной **Stellar Burgers**. Тесты покрывают критические пути пользователя, включая процессы регистрации, авторизации и навигации по основному каталогу.

## Стек технологий
* **Язык разработки:** Java 
* **Тестовый фреймворк:** JUnit 4
* **Инструмент автоматизации UI:** Selenium WebDriver
* **Взаимодействие с API (предусловия и очистка):** RestAssured
* **Архитектурный паттерн:** Page Object Model (POM)
* **Сборщик проектов:** Maven
* **Отчетность:** Allure Report
* **Тестируемые браузеры:** Google Chrome, Яндекс Браузер

---

## Реализованный функционал и покрытие тестами

### 1. Регистрация пользователей
* Проверка успешной регистрации с валидными данными.
* Валидация отображения ошибки при попытке задать некорректный пароль (длиной менее 6 символов).

### 2. Аутентификация (Вход в систему)
Проверка успешной авторизации пользователя через различные UI-элементы интерфейса:
* Кнопка «Войти в аккаунт» на главной странице.
* Кнопка «Личный кабинет» в шапке сайта.
* Ссылка перехода в форме регистрации.
* Ссылка перехода в форме восстановления пароля.

### 3. Раздел «Конструктор»
* Проверка корректности переходов и переключения табов к соответствующим разделам ингредиентов: «Булки», «Соусы», «Начинки».

## Архитектура проекта и особенности реализации

* **Page Object Model (POM):** Для минимизации дублирования кода и упрощения поддержки тестов логика страниц была полностью отделена от логики самих проверок. Для каждого ключевого экрана создан свой класс-страница, инкапсулирующий локаторы элементов (`By`) и методы действий с ними.
* **Гибридный подход (UI + API для подготовки и очистки данных):** 
  * Для тестов, требующих наличия существующего аккаунта (сценарии входа), **пользователи создавались напрямую через API** с помощью RestAssured в блоке `@Before`.
  * После завершения каждого теста в блоке `@After` реализовано **автоматическое удаление созданных пользователей через API**.
  * Это позволило значительно ускорить прогон, исключить хрупкие шаги регистрации на UI и гарантировать независимость и чистоту окружения при повторных запусках.
* **Кроссбраузерность:** Конфигурация WebDriver вынесена в базовый тестовый класс, позволяя динамически инициализировать нужный браузер. Фреймворк успешно протестирован и обеспечивает стабильный прогон тестов как в **Google Chrome**, так и в **Яндекс Браузере**.
* **Ожидания:** Использованы явные ожидания (`WebDriverWait`) для обеспечения стабильного взаимодействия с асинхронно загружающимися элементами интерфейса, что предотвращает появление «флакающих» (flaky) тестов.

## Запуск тестов и генерация Allure-отчета

### 1. Запуск автоматических тестов
Для прогона UI-тестов выполните команду:
```
mvn clean test
```

### 2. Просмотр отчетов Allure
После завершения тестов соберите и откройте интерактивный Allure-отчет в браузере с помощью команды:
```
mvn allure:serve
```
